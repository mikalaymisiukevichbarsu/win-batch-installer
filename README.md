# Win Batch Installer — инструкция по развёртыванию (v1.2.0)

Пошаговая инструкция для текущей версии проекта. Если ты разворачивал
v1.0.0 — изменились **состав файлов**, **версия в `package.json`** и
**поведение эндпоинтов**, поэтому шаг 1 и шаг 3 стоит перечитать.

---

## Что изменилось с прошлой версии инструкции

| Было | Стало |
|---|---|
| 8 файлов, всё в `api/` и `public/` | **+ папка `lib/`** с двумя файлами: `lib/db.js`, `lib/slug.js` |
| `package.json` v1.0.0, без `"type": "module"` | v1.2.0, **с `"type": "module"`** |
| `/run` на свежей базе возвращал `[ERROR] No valid programs found`, пока кто-нибудь не откроет главную | **`/run` сам засеивает базу** — ссылку можно давать сразу |
| Путь установки проверялся «на вырезание» символов | Путь **валидируется**: корень `C:\`, UNC `\\server\share`, кириллица, пробелы и `(x86)` работают; мусор → `[ERROR] Invalid installation path format.` |
| Любой пароль пускал в админку | Админка проверяет пароль через `HEAD /api/programs` (200/401) |
| Аргументы MSI и Telegram терялись при запуске | Исправлено — тихая установка MSI и Inno Setup работает |
| Кириллическое название программы ломало создание | Транслитерируется: «Моя программа» → `moya-programma` |
| Имена программ из базы вставлялись в HTML | Экранируются (закрыт XSS в админке и на главной) |

Имена переменных окружения **не изменились** — при обновлении существующего
проекта на Vercel заново вводить их не нужно.

## Шаг 1: Подготовка репозитория

1. Создай новый репозиторий на GitHub.
2. Загрузи **все** файлы проекта. Важно: вместе с папкой `lib/` — если
   загружать файлы по одному, её легко пропустить, и функции упадут
   с ошибкой `Cannot find module '../lib/db.js'`.

   Итоговая структура в корне репозитория:

   ```
   win-batch-installer/
   ├── api/
   │   ├── programs.js          # CRUD + авторизация
   │   └── run.js               # генератор PowerShell-скрипта
   ├── lib/
   │   ├── db.js                # подключение к Redis + сидинг дефолтов
   │   └── slug.js              # транслитерация названий в id
   ├── public/
   │   ├── index.html           # выбор программ для пользователя
   │   ├── admin.html           # админ-панель
   │   └── style.css            # необязательные стили (Tailwind идёт с CDN)
   ├── package.json
   ├── vercel.json
   └── .gitignore
   ```

3. Убедись, что в корне есть `package.json` и `vercel.json`.
   `node_modules/` коммитить не нужно — Vercel установит зависимости сам
   (единственная зависимость: `@upstash/redis`).

> Проверка без деплоя: `lib/` больше нигде не упоминается, кроме
> `import ... from '../lib/db.js'` в обоих файлах `api/`. Если папки нет —
> увидишь `FUNCTION_INVOCATION_FAILED` в логах Vercel.

## Шаг 2: Настройка Upstash Redis (база данных)

1. Зарегистрируйся на [upstash.com](https://upstash.com) (есть бесплатный тариф).
2. Создай новую базу **Redis**. Регион выбирай ближайший к пользователям
   (для России/СНГ обычно подходит eu-central-1).
3. В панели базы открой раздел **REST API**.

### ⚠️ Про названия переменных — здесь чаще всего ошибаются

Upstash показывает переменные как `UPSTASH_REDIS_REST_URL` и
`UPSTASH_REDIS_REST_TOKEN`, **а код читает `KV_REST_API_URL` и
`KV_REST_API_TOKEN`**. Это разные имена для одних и тех же значений.

Выбери один из двух вариантов:

**Вариант A (как в шаге 3):** скопируй *значения* и в Vercel введи их под
именами `KV_REST_API_URL` / `KV_REST_API_TOKEN`.

**Вариант B:** при импорте проекта на Vercel зайди в **Storage → Upstash →
Connect**, тогда интеграция создаст переменные с именами `KV_*` автоматически,
и вводить их руками не придётся.

**Вариант C:** переименуй в коде `lib/db.js` под имена Upstash:

```js
url: process.env.UPSTASH_REDIS_REST_URL,
token: process.env.UPSTASH_REDIS_REST_TOKEN,
```

Главное — имя в Vercel и имя в коде должны совпадать.

## Шаг 3: Развёртывание на Vercel

1. Зайди на [vercel.com](https://vercel.com) и импортируй свой GitHub-репозиторий.
2. **Framework Preset: Other** (важно! не React/Next.js).
3. **Build Command:** оставь пустым.
4. **Output Directory:** `public`.
5. **Node.js Version:** `20.x` или `22.x` (в проекте `"type": "module"`,
   старые версии не нужны).
6. Во вкладке **Environment Variables** добавь три переменные:

   | Имя | Значение |
   |---|---|
   | `KV_REST_API_URL` | URL из Upstash (тот, что там называется `UPSTASH_REDIS_REST_URL`) |
   | `KV_REST_API_TOKEN` | токен из Upstash (`UPSTASH_REDIS_REST_TOKEN`) |
   | `ADMIN_PASSWORD` | придумай надёжный пароль для админки |

   `ADMIN_PASSWORD` **обязателен**: если его не задать, вход в админку не
   сработает ни с каким паролем (сервер отвечает 401).

7. Нажми **Deploy**.

## Шаг 4: Привязка домена (для красивой команды)

1. После деплоя перейди в настройки проекта → **Domains**.
2. Добавь свой домен (например, `install.mydomain.com`).
3. Настрой DNS согласно инструкциям Vercel.
4. Теперь команда выглядит профессионально — её и выдаёт кнопка
   «📋 Копировать» на главной странице:

   ```powershell
   irm "https://install.mydomain.com/run?ids=chrome,7zip&path=D:\Programs" | iex
   ```

   Кодировать путь вручную не нужно — Vercel сам раскодирует `%3A` и `%5C`,
   так что `path=D:\Programs` и `path=D%3A%5CPrograms` работают одинаково.

## Шаг 5: Проверка после деплоя

Открой в браузере (или через `curl`):

| Что проверить | Ожидаемый результат |
|---|---|
| `https://твой-домен/` | страница с плитками программ (Chrome, 7-Zip, VLC, Notepad++, Telegram) |
| `https://твой-домен/api/programs` | JSON-массив из 5 программ |
| `https://твой-домен/run?ids=chrome&path=D:\Soft` | текст, начинающийся с `# Win Batch Installer Script v1.2.0` |
| `https://твой-домен/run?ids=chrome&path=мусор` | `Write-Host "[ERROR] Invalid installation path format. Use C:\Apps or \\server\share."` |
| `https://твой-домен/admin.html` + неверный пароль | «Неверный пароль», дашборд не открывается |
| `https://твой-домен/admin.html` + верный пароль | таблица программ, можно добавлять/править/удалять |

Последний пункт проверяет связку с базой: если пароль верный, но таблица
пустая или появляется ошибка — проблема в переменных `KV_*` (см. шаг 2).

Тест «всё работает целиком»: в админке добавь программу с русским названием
(например «Моя программа») и прямой ссылкой на `.exe` — она должна появиться
на главной, а её id стать `moya-programma`.

## Обновление версии в будущем

Vercel пересобирает проект при каждом пуше в репозиторий. Переменные
окружения и база сохраняются, программы из Redis не теряются — сидинг
добавляет только отсутствующие записи и **не перезаписывает** то, что ты
отредактировал через админку.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `Cannot find module '../lib/db.js'` | папка `lib/` не загружена в репозиторий |
| `FUNCTION_INVOCATION_FAILED` в логах | не заданы `KV_REST_API_URL` / `KV_REST_API_TOKEN`, либо перепутаны имена `UPSTASH_*` и `KV_*` |
| Список программ пустой, ошибок нет | неверный `KV_REST_API_URL` (например, скопирован URL базы вместо REST URL) |
| В админку не пускает даже с верным паролем | не задан `ADMIN_PASSWORD` |
| На `/` отдаётся 404 | проверь **Output Directory = `public`** — именно оно заставляет Vercel отдавать `public/index.html` по корню |
| `irm` выдаёт ошибку про SSL/TLS | скрипт сам ставит TLS 1.2 первой строкой; убеждайся, что скачивается именно свежий ответ (Vercel отдаёт `no-store`) |

## Безопасность — прочитать перед публикацией

1. **`/run` публичен по замыслу.** Любой, у кого есть ссылка, получит скрипт
   тихой установки. Не публикуй ссылку с `ids` там, где её увидят посторонние.
2. **`ADMIN_PASSWORD` — единственный фактор защиты админки**, и на подбор
   пароля нет ограничения частоты. Ставь длинный случайный пароль.
3. **`GET /api/programs` открыт специально** — главная страница должна
   показывать список без авторизации. Меняются данные только с паролем.
4. **Скачанный установщик не проверяется по хэшу.** Скрипт качает файл по
   URL из базы и запускает его. Доверяй только тем ссылкам, которые сам
   добавил, и держи админку закрытой.
5. **Скрипт не имеет таймаута на скачивание.** Если сервер-источник зависнет,
   окно PowerShell будет ждать.

## Локальный запуск (необязательно)

```powershell
npm install
npx vercel dev      # подхватит переменные из .env.local
```

Файл `.env.local` (уже в `.gitignore`):

```
KV_REST_API_URL=https://xxx.upstash.io
KV_REST_API_TOKEN=xxxxxxxx
ADMIN_PASSWORD=local-dev-password
```
